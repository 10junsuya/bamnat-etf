# 대표 지시 모음 (AI 팀 필독)

대표님이 지금까지 고치라고 하거나, 다시 조사하라고 하거나, 더 자세히 하라고 한 것을 모은 문서예요.
**대표님이 다시 말하지 않아도, 대표님이 보지 못한 곳에서도** 같은 문제를 스스로 찾아 고치거나 보고하는 게 목적이에요.

- 모든 AI는 일을 시작할 때 `ops/LESSONS.md`, `ops/knowledge/README.md`와 함께 이 문서를 읽어요 (RULES 0장).
- 한 번 들은 지시는 **그 자리 하나가 아니라 같은 종류 전체**에 적용해요. 예: "이 칸이 예시로 잘못 표시됐어" → 앱 전체에서 잘못 표시된 칸을 다 찾아요.
- 고칠 수 있는 범위(RULES 3장)는 고치고 게시판에 남겨요. 범위 밖이면 고치지 말고 "지시 모음 n번 위반 발견"으로 보고해요.

## 1. 말투·글

1. **한국어로만.** 보고서·알림·앱 글자 모두. 영어로 답했다가 지적받은 적 있어요. 영어 고유명사는 괜찮지만 문장은 한국어로 써요. (2026-11-16)
2. **영어 기사 제목을 그대로 보여주지 않아요.** 우리 말 한 줄로 새로 쓰고 출처 링크만 붙여요. 기사 본문은 옮기지 않아요. (2026-11-16)
3. **일반인 눈높이.** 프리마켓·애프터마켓·iNAV 같은 말은 일반인이 모른다고 보고 쉬운 말이나 짧은 설명을 붙여요. 업종 전문 용어로 범위를 좁히지 않아요. 예: "발사 결과" → "회사 이벤트 결과(제품 발표, 로켓 발사 등)". (2026-11-16)
4. **보고는 짧게, 핵심 숫자 먼저.** "숫자 두 개로 보여줘"처럼, 결론과 숫자를 맨 앞에 두고 과정 설명은 줄여요. (2026-11-16)
5. 이모지는 쓰지 않아요. 금색은 강조 숫자에만 써요 (qa/DECISIONS.md).

## 2. 숫자·사실

6. **확인 못 한 숫자는 쓰지 않아요.** 계산한 숫자는 계산했다고 밝히고, 보도만 있으면 "보도"로 표시해요.
7. **이상하게 계속 같은 숫자는 의심해요.** 환율 효과가 계속 0%로 나왔는데, 실제로는 하루 한 번만 바뀌는 환율을 쓰고 있었어요. 0·같은 값·빈칸이 반복되면 원인을 찾아요. (2026-11-16)
8. **'실제'와 '샘플' 표시가 데이터와 맞아야 해요.** 실제 데이터인데 '예시'·'샘플'로 표시됐거나, 샘플인데 실제처럼 보이면 바로 고쳐요. 대표님이 "말 안 해도 보이면 고쳐"라고 했어요. (2026-11-16)
9. **날짜·일정은 공식 출처로 확인해요.** 확인 못 한 일정은 "예정"으로 표시해요. 자동으로 받은 날짜도 말이 되는지 봐요. 예: FOMC 다음 회의가 '오늘'로 잡혔던 오류. (2026-11-16)
10. **정확도·성과는 솔직하게.** 좋게 보이게 다듬지 않아요. 왜 틀리는지(아시아 종목, 액티브 비중, 환율 시점)를 함께 적어요.

## 3. 화면·내용

11. **자세하지만 쏟아지지 않게.** 회사 설명은 아주 자세히 쓰되, 새 칸을 늘리지 말고 기존 카드 안에 접어서 넣어요(눌러서 펼치기). (2026-11-15)
12. **가짜 자리 채움 금지.** "[예시] 뉴스가 여기에 들어가요" 같은 빈 자리 문구를 남기지 않아요. 실제 내용이 없으면 칸을 숨겨요. (2026-11-16)
13. 앱은 중립이에요. 매수·매도 권유, "지금 사도 된다" 같은 말은 쓰지 않아요.
14. **실시간성이 강점이에요.** 실적은 발표 뒤 1시간 안에, 회사 소식은 30~40분 안에 반영되는지 늘 확인해요. 늦으면 원인을 보고해요.

## 4. 전달·확인

15. **약속한 전달물이 실제로 도착했는지 확인해요.** 바탕화면 GNOMON 폴더에 회의록·브리핑이 빠졌던 적 있어요. 만들었다고 끝이 아니고, 폴더·메일·앱에 실제로 있는지 봐요. (2026-11-16)
16. **GNOMON 폴더는 단순하게, PDF로만.** 보고서·회의록·중요 결정만 두고, 내용이 겹치는 문서는 합쳐요. 예: 팀 역할 + 일정 규칙 → 「노몬 운영 안내」. (2026-11-16)
17. **고친 뒤에는 직접 열어서 확인해요.** 앱은 브라우저로 열고, PDF는 페이지를 보고, 서버는 실제로 불러 봐요.

## 5. 일하는 방식

18. **"의견만" · "수정하지 마"는 의견만이에요.** 그 말을 들으면 파일을 바꾸지 않아요.
19. **긴 작업은 단계별로 끊어요.** 업종별·단계별로 하나씩 끝내고, 대표님이 "하라"고 하면 다음으로 넘어가요. (2026-11-15)
20. **취향은 선택지로 물어요.** 디자인·이름처럼 취향이 갈리는 건 2~3개 안을 보여줘요.
21. **AI 팀은 스스로 공부해요.** 싱크탱크·연준·주요 매체 분석을 읽고 공부 노트를 남기고, 실수는 교훈으로 남겨요. (2026-11-16)

## 6. 보안·공개

22. 앱에 샘플이 남아 있으면 공개하지 않아요. 공개는 대표님이 따로 승인해요. (2026-11-16)
23. 공개 저장소에 개인정보(메일·전화·계좌·키)를 적지 않아요. 대표님 메일 주소가 결정 기록에 적혀 있던 적 있어요. (2026-11-16)
24. 보안은 "이용자는 막지 않고 앱을 지킨다"예요. 이용 횟수 제한은 두지 않아요. (2026-11-16)

아래 질문으로 앱과 산출물을 훑어요. "예"가 나오면 고칠 수 있는 범위는 고치고, 아니면 보고해요.

- [ ] 일정 중에 지난 날짜·오늘로 잘못 잡힌 날짜·출처 없는 날짜가 있나? (9)
- [ ] 일반인이 모를 용어가 설명 없이 나오나? (3)
- [ ] 실적 발표 뒤 1시간이 넘도록 카드가 그대로인 회사가 있나? 소식 반영이 늦었나? (14)
- [ ] 어제 약속한 PDF가 GNOMON 폴더·메일에 실제로 도착했나? (15)

## 새 지시를 더하는 법

- 대표님이 대화·승인 답장·게시판 어디서든 고치라고 하거나 더 조사하라고 하면, 그 말을 들은 AI(또는 Claude)가 이 문서 맨 아래 "새로 들어온 지시"에 날짜와 함께 적어요.
- Conrad가 아침마다 그것을 "같은 종류 전체에 적용되는 규칙"으로 다듬어 위 1~6장에 넣어요. 예: "이 문구 틀렸어"라는 말에서 "같은 종류의 문구를 앱 전체에서 찾기"라는 규칙을 만들어요.
- 이 문서의 규칙을 지우거나 약하게 바꾸는 것은 대표 승인 뒤에만 해요.
