# 실적 카드·실적 일정 분석 고치는 법 (Tally)

> 시작할 때 `ops/LESSONS.md`(실수 노트)와 `ops/knowledge/README.md`(시장 공부 요약)를 먼저 읽어요 (ops/RULES.md 0장). 새로 배운 교훈은 tally.md 에 "교훈"으로 남겨요.

회사 화면 맨 위 「실적」 카드의 원본은 `data/earnings.json` 이에요. `index.html` 은 `python3 scripts/check_data.py --embed` 로만 바뀌어요.

## 카드 한 곳의 모양
- `p`: 기간 (예: "3분기 · 2026년 7~9월", 회계연도가 다르면 "2분기 · 2026년 7~9월")
- `tag`: 1년 전보다 매출 증감 (예: "+17%", 모르면 "—")
- `rows`: [이름, 값] 3~4줄 (매출, 핵심 부문, 이익, 전망 등)
- `note`: 1~2문장. 무엇이 이끌었는지 + 주의할 점. **계산한 값(성장률로 거꾸로 구한 1년 전 매출 등)은 반드시 여기 밝혀요.**
- `src`: [이름, 링크] 2~3개. 회사 발표·SEC 공시를 먼저, 예상치 출처를 함께.
- `chart` (금액은 **백만 단위**, `cur` 는 usd·eur·cad·krw·twd·cny 중 하나)
  - `now`: [기간 이름, 이번 매출] · `prev`: ["1년 전", 매출] (모르면 빼요)
  - `est`: 발표 **전** 애널리스트 매출 예상 (모르면 null — 지어내지 않아요)
  - `next`: `label`(다음 분기 이름), `guide`([낮은, 높은] 회사 분기 전망 또는 null), `cons`(다음 분기 애널리스트 예상 또는 null), `asof`("11/3" 처럼 기준일), `when`("2027년 2월 초 (예상)"), `gtext`(분기 전망이 없고 연간 전망만 있을 때 한 줄)
  - `metric`: 매출이 아닌 다른 숫자를 그릴 때만 (예: "소프트웨어 매출")

## 출처 규칙
- 실적 숫자는 회사 발표·SEC 공시가 기준. 언론 정리는 회사 발표와 맞을 때만.
- 애널리스트 예상은 공식이 아니에요. 출처마다 다르면 하나를 고르고 `note` 에 범위를 적어요.
- 확인 못 한 숫자는 넣지 않아요. 매수·매도 표현은 쓰지 않아요.

## 순서
1. `git pull --rebase`
2. `scripts/earnings_card.py` 의 `card()` 로 고치고 `save()`
3. `python3 scripts/check_data.py --embed` 통과
4. `data/earnings.json`, `data/events.json`(바꿨으면), `index.html`, `ops/board/tally.md` 를 한 커밋: `실적 카드: <회사들> (출처: <대표 URL>)`
5. `git pull --rebase` 후 다시 `check_data.py` 확인, push (충돌 시 최대 3번)

## 실적 일정 분석 (data/events.json, type "earn")
실적 일정 페이지에서 회사를 누르면 나오는 분석이에요. 실적 카드와 **같은 차례에 함께** 고쳐요.

- **발표 후:** 해당 일정에 `"done": true` 와 `card` 를 넣어요. 모양은 `2026-11-13 AMAT` 일정과 똑같이:
  - `real: true`, `asof`: 오늘 날짜
  - `sum`: 2문장 (예상·회사 전망과 비교해 어땠는지 + 무슨 뜻인지)
  - `tiles`: 2~4개 `[이름, 값, 한 줄 비교, [실제, 비교 기준]]` — 마지막 숫자 쌍은 예상과 비교할 때만 (빨강=예상보다 높음, 파랑=낮음)
  - `check`: 핵심 정리 2~3문장 · `detail`: 배경 1~2문단 · `src`: 회사 발표를 먼저
- **발표 전:** 앱 종목(`index.html` STOCKS)인 회사의 실적 날짜가 **회사 공식 발표로 확정**되면 21일 안 일정을 새로 넣어요: `d`, `t`, `type: "earn"`, `title`("<회사> 실적 발표"), `when`(한국 시간, 예: "06:05 · 미국 장 마감 후"), `q`(분기), `watch`(볼 점 3개).
- 날짜가 바뀌면 고치고, 보도만 있으면 `when` 끝에 " · 변동 가능성 보도".
- 매수·매도 표현, 주가 전망은 쓰지 않아요. "예상보다 좋으면/못 미치면" 해석(`ifGood`·`ifBad`)은 쓰지 않아요.

## 7. 시장은 이렇게 봤어요 (card.views, 대표 지시 2026-11-16)
실적 카드(`card`)를 쓸 때 `card.views`도 함께 써요. 자세한 방법은 `ops/RULES.md` 6-2.
- body 2~3단락: ① 예상·회사 전망과 비교한 결과 ② 발표 뒤 주가 반응(시간외·다음 날, 확인된 숫자만) ③ 애널리스트·매체 해석 — 서로 다른 시각을 함께, 누구의 해석인지 표시.
- items 3~5개: CNBC 실적 피드·야후 종목 기사·Bloomberg·WSJ·Reuters 제목에서 이 회사 실적을 다룬 것 → 한국어 한 줄 + 매체 + 링크 + 날짜 + "보도".
- 발표 직후 기사가 아직 없으면 card 먼저 올리고, 다음 차례(30분 뒤)에 views를 더해요.
